PROBLEM STATEMENT
Even after Phases 1 and 2 are complete, operating the lab still requires a lecturer to know Ansible commands and Proxmox administration. Students must be given credentials manually. There is no booking system, no browser-based VM access, and no self-service experience. The lab cannot scale to full faculty use without an accessible management portal.
RESEARCH QUESTIONS
  1. How can a web portal abstract Proxmox and Ansible complexity so a lecturer with no Linux experience can deploy a class lab in under 60 seconds?
  2. What is the minimum viable noVNC/Guacamole integration for students to access VM consoles directly in a browser without any client install?
  3. How should automated time-based lab cleanup be implemented to guarantee VM destruction and data sanitisation after each booking slot?
SCOPE & TASKS (3-PORTAL SYSTEM)
  1. 01Student Portal — self-service lab booking (class type, time slot); view assigned Acer IP and VM credentials; access VM console in browser via noVNC/Guacamole.
  2. 02Lecturer Portal — 1-click class deployment (select topology, push to Acers via FYP-1C Ansible API); monitor student VM status; manual reset / lab end.
  3. 03Admin Portal — Acer fleet health view; VM image library management; user account management; resource usage analytics.
  4. 04Backend: Proxmox API integration (CRUD VMs), Ansible API integration (trigger playbooks), SQLite/PostgreSQL booking database.
  5. 05Automated cleanup: time-slot expiry triggers VM destruction; generate activity log for lecturer review.
